## 2. Running it locally — the part that wasted the most time

Three separate traps, all of which look like application bugs.

**Local.app squats `127.0.0.1:4000` on this machine.** Two listeners end up on
port 4000 and a request to `localhost:4000` reaches the wrong one and hangs.
Use the LAN address the API prints on boot (`http://10.144.7.178:4000` here),
or a different port. `lsof -nP -iTCP:4000 -sTCP:LISTEN` shows who holds it —
and never `kill $(lsof -ti tcp:4000)`, which also kills Chrome.

**`PUBLIC_BASE_URL` decides where phones fetch images from.** Unset, it defaults
to `http://localhost:<port>`, and on a real device `localhost` is the device —
so every image 404s and the app looks like it lost its art. `docs/deploy.md`
says this outright and it still cost an hour. Set it to whatever the client can
actually reach.

**Which database you get changes what the app looks like.** Loading the whole
`.env` gives production Postgres and Supabase auth; omitting `DATABASE_URL`
gives `MemoryRepository`. They are not interchangeable for eyeballing the app:

- the in-memory store hardcodes demo signals for **three** old stories
  (`repo/memory.ts:77-79`), so Itachi sits at zero likes and sinks to the bottom
  of Top Ranked, while production is seeded by `seed:social` with Itachi at
  158k and featured first.
- it has no real accounts, so the library is empty.

A local build that looks "wrong" is almost always this. Check `/health`:
`persistence: in-process` vs `postgres`.

Two recipes:

```bash
# Looks like production (real catalogue, real account, writes are real).
cd services/api && env $(grep -E '^(OPENAI_API_KEY|SUPABASE_URL|SUPABASE_ANON_KEY|DATABASE_URL|MEDIA_EPOCH)=' ../../.env | xargs) \
  PUBLIC_BASE_URL="http://<lan-ip>:4000" npx tsx src/index.ts

# Throwaway data, fixtures straight from the repo — the only way to see an
# unpublished story change without migrating.
cd services/api && OPENAI_API_KEY=… PORT=4100 PUBLIC_BASE_URL="http://127.0.0.1:4100" npx tsx src/index.ts
```

**Pointing a build somewhere without touching `Local.xcconfig`:**

```bash
xcodebuild … PLOTBREAK_API_URL='http://…' PLOTBREAK_SUPABASE_ANON_KEY='' PLOTBREAK_SUPABASE_URL='' build
```

Command-line settings beat the xcconfig and leave no file behind to forget. The
empty Supabase values force the guest path, which is what you want against a
`dev-token` API — otherwise the app shows a sign-in wall it can never satisfy.
And **`Release.xcconfig` includes `Local.xcconfig`**, so anything left in that
file ships to the App Store. Always read the archive back:

```bash
plutil -extract PLOTBREAK_API_URL raw <App>/Info.plist
```

## 3. Giving a story an opening cinematic

Three frames before the first beat. Only Itachi has one; every other story has
an empty `prologue` and opens exactly as before.

1. **Write the shots** in `infra/scripts/prologue-art.ts` under `SHOTS`, keyed by
   story. Then `npx tsx infra/scripts/prologue-art.ts --story=<name>`.
2. **Optimise**: `npx tsx infra/scripts/optimize-art.ts`. Masters are gitignored;
   the `.webp` are committed and are what deploys.
3. **Add the panels** to the story fixture as `prologue: [...]` beside `opening`.
4. **Deploy the API, then `npm run migrate`.** In that order, always — see §4.

**What makes the art work.** The first attempt produced a handsome generic
village that read as stock anime, because the prompts hedged: "a slim figure in
dark shinobi clothes", "a round paper-fan crest". For a story whose whole draw
is recognition that is worse than no art at all. Itachi's own `coverDirection`
already had the answer — it names things outright: "Mangekyo Sharingan", "the
black Akatsuki cloak with large red clouds", "Leaf forehead protector scratched
horizontally". Naming the cliff with four carved stone faces, the red-over-white
fan on every wall, the spiral-leaf protector and Sasuke's navy high collar is
what turned it from generic to unmistakable.

Two constraints that are not style preferences:

- **No text in the art.** It cannot be translated or read aloud. Headlines are
  story data and go through the normal i18n path.
- **Describe young characters by costume, never by age.** Stacking age words
  trips the provider's classifier and the whole request is refused;
  `generate-art.ts` documents Ace's cover being rejected twice over this.

Three panels, capped at four in the schema. The pictures are the narration,
which is what earns the opening beat the right to be four lines and a question
instead of 250 words of scene-setting.

## 4. Ordering rules that have already cost real money

**Schema before the data that uses it.** A new `StoryVersion` field must be
deployed before `migrate` publishes any version carrying it, or the running
build rejects the new version and `/v1/discover` answers 500 while `/health`
says fine. That is the `calledName` incident, and `prologue` was added as a
defaulted field specifically so old versions keep parsing.

**Adding a field republishes every story.** `prologue` defaulting to `[]`
changed all 26 definitions, so migrate reported "0 new, 26 revised" rather than
1. Harmless — sessions pin their version — but every story's version bumps, and
media URLs carry `?v=<version>`, so the whole catalogue cache-misses once.
Expect it for any future field.

**Never run the art optimiser without checking what it will overwrite.** It
assumes the `.png` beside a `.webp` is the master. For the v4 titled covers that
is backwards: the wordmark is composited into the `.webp`. Running it to shrink
three new frames regenerated 25 covers from stale untitled masters, `git add -A`
committed them, and production served wordmark-less covers for about twenty
minutes. `63c7098` adds a guard (skip a `.webp` newer than its `.png`), but the
habit matters more than the guard:

```bash
git diff --stat main -- infra/seed/assets    # before any push touching art
```

Typecheck, 2,682 tests and a full smoke run all passed while that was broken.
**No gate in this repo looks at binary assets.**

## 6. If you are starting a new story next

`docs/authoring-principles.md` and `docs/story-bibles/` are the real references.
The mechanical path is: write the fixture in `packages/test-fixtures/src/`, add
it to `LAUNCH_CATALOG` in `index.ts`, generate art, `npm run migrate`. The
launch-catalog tests will fail if a world introduces an expression the reaction
map does not know, or ships without `withDerivedAssetKeys` — both are deliberate
and both have caught real breakage.

Worth knowing before writing: **production runs the LLM-first `runTurnPure`
path, not the deterministic engine.** The storyteller reads `worldBrief`, which
is built from the bible — premise, hard canon, cast with their hidden drives and
secrets, places, factions, threads, world events, endings. That is the surface
that matters. Quests, checks and relationship arithmetic are not consulted at
turn time. See the top of `CLAUDE.md`.
